# Caveats

- Don't delete and recreate an ActorTemplate under the same name while a conversation using it might still need crash recovery as it may result in cold start during resume.
- `registry.substrate[].suspend_actor_timeout` defaults to 11 minutes and normally doesn't need to be set. It must stay longer than the Agent Substrate API server's own per-RPC deadline (`maxRPCDeadline` in `cmd/ateapi/main.go`, 10 minutes in both the previously pinned version and v0.2.0), so that checkpointd never abandons a `SuspendActor` that Substrate is still working on. An abandoned suspend leaves the actor SUSPENDING, and re-suspending it may fail and crash the actor; checkpointd then reverts it to its last committed checkpoint and replays the turn. That keeps the state consistent but redoes the turn's work, and a timeout shorter than a legitimately slow suspend (large snapshots, slow object storage) repeats this on every retry so the turn never commits. If you run a Substrate deployment with a different `maxRPCDeadline`, set the timeout a minute or two past that value.
- `CancelTask` never signals the agent's own running logic (`AgentExecutor.Cancel` is never called), so don't rely on cancellation to trigger agent-side cleanup.
- Clients should store the `tenant` field from a reply's `Metadata` and resend it on later `GetTask`/`CancelTask`/`SendMessage` calls for the same task, to avoid an ambiguous-TaskID lookup failing as not-found.
- An `externalVolumeTemplate` volume keeps whatever the discarded execution wrote, so a retried turn can see side effects it already made. A `durableDir` volume is part of the snapshot, so it is rewound with it.
